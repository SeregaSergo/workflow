# Конфигурируемая остановка пайплайна (`pause_before`)

**Дата:** 2026-05-19
**Источник:** `tasks/04-stop-stage-conf`

## Проблема

Сейчас единственная "остановка" в пайплайне жёстко зашита в коде фазы `review`:
[src/wf/phases/review.py:99-102](../../../src/wf/phases/review.py#L99-L102) возвращает
`PhaseResult.paused(...)`, если у ревью нет блока `<feedback>`. Это значит, что:

- Точка остановки приколочена к одной фазе и одному условию.
- Чтобы изменить поведение (например, паузиться перед `mr` или вообще не паузиться),
  нужно править код.

Хотим: декларативный список фаз в YAML-конфиге, перед которыми движок останавливается
и просит пользователя сделать `wf resume`.

## Решение

Добавляем поле `pause_before` в `WorkflowSpec`. Движок проверяет его перед каждым
запуском фазы и эмитит `paused`, если текущая фаза в списке и пауза для неё ещё не была
"израсходована" в этом заходе.

### Конфиг

В секции `workflows.<name>` появляется поле `pause_before: list[str]` — список имён фаз.

```yaml
workflows:
  coding:
    notify_channel_id: "REPLACE_ME"
    reviewers: []
    pause_before: [mr]    # пример: пауза перед созданием MR
```

Дефолт — пустой список (`[]`). Старые конфиги без поля → нет пауз. Чтобы повторить
текущее поведение фазы `review`, нужно прописать `pause_before: [mr]` руками.

Валидация (одноразово при загрузке workflow): каждое имя в `pause_before` должно
существовать в `workflow.phases`. Иначе — понятная ошибка с указанием неизвестного имени.

### State

Добавляем поле `pause_consumed_for: str | None = None`. Это "залипший" флаг, который
говорит: для фазы N пауза уже была эмитнута, второй раз эмитить не надо.

Инварианты:
- При входе в фазу N движок проверяет `state.pause_consumed_for == N`. Если да — пауза
  пропускается (это второй заход после `wf resume`). Если нет, и `N ∈ pause_before` —
  ставим `pause_consumed_for = N`, сейвим, возвращаем `paused`.
- После любого успешного перехода (`_resolve_next` обработал не-`None` результат
  transition — будь то обычная строка или `RepeatAt`) движок сбрасывает
  `pause_consumed_for = None`. Это значит, что при цикле `review → plan → ... → review`
  пауза перед `mr` сработает каждую итерацию.

### Семантика

- Пауза эмитится **до** запуска фазы. Артефакты этой фазы ещё не созданы; пользователь
  смотрит результат **предыдущей** фазы.
- `wf resume` ничего нового не делает: просто повторно вызывает `step()`. Так как
  `pause_consumed_for == current_stage`, пауза пропускается и фаза запускается.
- При повторном цикле через `RepeatAt(plan)` пауза перед `mr` будет на каждой итерации.

### Что **не** делаем (YAGNI)

- Не добавляем `pause_after` — паузу после фазы можно выразить через `pause_before` следующей.
- Не делаем терминальную остановку (`stop_after`, `terminal=done`) — пользователь явно
  выбрал только pause-семантику.
- Не делаем условные паузы (по итерации, по результату фазы, по содержимому артефакта).
- Не делаем CLI-флаги для разовой паузы (типа `wf start --pause-before mr`).

### Сломанная совместимость

Это **намеренное** изменение: пользователи с существующим `~/.wf/config.yaml` без поля
`pause_before` получат пайплайн **без пауз** — фаза `review` больше не остановится
сама. Чтобы вернуть прежнее поведение, нужно вручную добавить
`workflows.coding.pause_before: [mr]` в конфиг.

Это согласовано (см. обсуждение в брейншторме): дефолт пустой, пользователи опт-инят.
